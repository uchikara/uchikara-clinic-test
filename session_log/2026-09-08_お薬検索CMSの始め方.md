# お薬検索CMSの始め方

## 1. 作業用のサイトを取得する

この非公開リポジトリにアクセスできるGitHubアカウントで作業してください。

リポジトリ: https://github.com/uchikara/uchikara-clinic-test

AIにこのリポジトリをPCの作業フォルダへcloneしてもらいます。GitHubに変更を戻せるよう、サイト側は「Download ZIP」ではなくcloneを使います。

## 2. 教材用コピーをダウンロードする

教材ダウンロードページ:
https://github.com/uchikara/uchikara-clinic-test/releases/tag/training-2026-09-08

Assetsから `prescription-training-2026-09-08.zip`（約159MB）をダウンロードし、展開します。教材はサイトの作業フォルダの外に置いてください。リリース画面の自動生成「Source code (zip)」は教材ZIPではありません。

配置例:

```text
任意の作業フォルダ/
  uchikara-clinic-test/                 ← cloneしたサイト
  prescription-training-2026-09-08/     ← 展開した教材
```

教材内の `session_log/2026-09-08_教材の使い方.md` をAIに読ませます。
教材にはお薬526件、関連画像779点、検索コードと入力項目定義があります。元が下書きの19件も教材内では公開扱いですが、本番公開の承認を意味しません。

## 3. このプロンプトで始める

> このリポジトリと隣の教材フォルダを調べ、https://test.uchikara-clinic.com/prescription/ にお薬検索サイトを作ってください。薬の情報を私自身が追加・修正・公開／非公開にできる管理画面も作ってください。管理画面にはログインが必要です。目的の公開URLは上記で固定し、実装とデータの設計は私と相談して決めてください。
> 最初に教材内の使い方とリポジトリの自動公開設定を読み、私が必要とする操作と完成条件を確認してください。データの構造・取り込み方・画面・確認方法は、あなたと私で決めます。既存のお薬検索 https://uchikara-clinic.com/prescription/ も参考にしてください。
> 少数件で確認してから526件へ広げます。私自身が更新・検索・詳細表示・公開切り替え・誤操作からの復元を確認できるよう進めてください。薬の説明を推測で補完せず、不足や不一致は報告してください。
> 教材全体や秘密情報をリポジトリに入れず、必要な公開用データと実装を選んでください。作業対象はローカルとTESTだけです。本番サイト・本番DBは変更しません。TESTへの自動転送が未設定なら、勝手に有効化せずローカルで進め、不足設定を報告してください。

## 4. 修正と確認を繰り返す

AIと修正 → ローカルで本人が確認 → commit・push → GitHub Actionsの結果を確認、の順で進めます。

現時点ではGitHubの自動チェックは有効ですが、SSH設定未完了のためTESTへの自動転送は停止しています。pushだけではTESTは変わりません。管理者が公開設定を完了した後は、チェック成功時にTESTへ反映します。

既存の検証は静的42ページを前提としているため、CMS追加時には目的に合う検証へ見直してください。`npm run build` は既存WordPressから静的ページを再取得する処理です。作業中の変更を上書きし得るので、内容を理解するまでは実行しないでください。

TESTフォームの実送信停止とアクセス制限は引き渡し前に管理者側で確認が必要です。ローカル作業では外部へのメール・通知送信を無効にします。
